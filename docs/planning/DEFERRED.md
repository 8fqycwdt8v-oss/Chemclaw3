# DEFERRED

Consciously postponed items — each with the reason it is *not now* and the trigger that would
revisit it. Default is "off-the-shelf, defer until measured".

**This is a register of what is still pending, not a log of what was decided.** A closed item is
**deleted** from it in the commit that closes it; its ADR is the record, and `git log` is the
history. Recording closure by appending a status note below a stale row is what turned this file
into nine chronological sections describing each other, three of which had gone false (D-154).

Rows are grouped by **what would have to change** — the only axis that makes a trigger checkable.
Each names an anchor in the tree, so any row can be verified with one `grep`.

Each is a real optimization whose cost is currently zero. The measured current value is stated so
the trigger is checkable rather than a feeling.

(The *parsing* was quadratic too until 2026-08-14; that half is fixed and is not what this row waits on) | ~10⁴ reactions (~10⁸ comparisons per run); switch to per-reaction Postgres HNSW k-NN |
| **Substructure pattern-fingerprint prefilter** | `find_substructure_matches` bounds its scan to `substructure_scan_max_records` (5000) and matching runs in a worker thread under `substructure_match_timeout_seconds` (D-080). **The "warns on truncation, so both footguns are closed" clause was false and is corrected here** (D-2026-08-08-a-partial-answer-must-say-so): a 21-record store with cap 20 and the sole azide at id 900 returned `hits: []` under a verdict calling it "a genuine negative result" — the warning was a log line nobody acts on, not an answer the model reads. Screening with a pattern fingerprint first would raise the ceiling, but ECFP bits cannot screen substructures soundly — it needs a dedicated pattern-fingerprint column and index. Honest residual: the wall-clock bound frees the caller and the event loop, not the CPU (RDKit exposes no interruption hook); killing the work outright needs a subprocess | The truncation warning fires in real use, past ~10⁴ molecules |
| **`within=` id-array scaling** | Retrieval eligibility ships the full eligible-id list as one SQL array parameter; fine at 10³–10⁴ notes. **Filed as a scale concern, and that is the wrong register**: with the HNSW index restored (D-2026-08-08-a-derived-index-must-record-what-derived-it) `within=` is a *post-filter* over the ef_search candidate list, so it under-returns at fixture scale today — measured 5 of 8 rows at k=8. The array-size question is still a scale question; the recall question is not, and it is **answered**: re-measured after `ANALYZE`, the note index goes short on 0 of 20 queries and the document index on 1–2 of 20, and the two knobs that address that residual now exist and default to off (D-2026-08-13-analyze-first-and-the-recall-knobs-second) | The corpus approaches ~10⁵ notes — then index type/tag/currency columns instead |
| **Per-key in-flight dedup in the calculation store** | Two *concurrent* misses on one key both compute (benign last-writer-wins upsert); serializing needs cross-process locking | Duplicate expensive runs (real HPC/DFT) become a measured cost |
| **A supervisor narrowed below its specialists** | Delegation is currently unprovokable, and that is structural rather than a prompt problem: `reject_widening` requires specialists ⊆ supervisor, so the supervisor always already holds the tool that answers a question and delegating is a strictly longer path to it. Making the supervisor the *union* of its specialists rather than a superset of each would make delegation a capability question, and it inverts D-2026-08-10's invariant 1 — a security property — so it is a redesign rather than an adjustment | A deployment whose specialist surfaces are genuinely disjoint, so that narrowing the supervisor removes nothing it needs; **or** routing quality becomes a requirement rather than a measurement, which needs the ADR's surface score to show the partition is sound first |

## Gated on a capability, source or licence not in scope

Each waits on a concrete need or an external artifact, not on us.

**Two capabilities share one blocker: model weights fetched at runtime.** D-089 rejects runtime
external data, and D-135 shipped the amendment — a dataset *may* be vendored into the image at build
time, checksummed and licence-labelled (`data/vendored/`, `ingest/sources/vendored/`). So the trigger
for the ML-potential and tabular-FM rows has moved from "no mechanism exists" to "pick a
licence-clean artifact and add the build step", which is the same residual as BACKLOG's open
*vendor a real third-party corpus*.

**Retrosynthesis used to be counted as the third, and it is not.** Re-checked 2026-08-13: its
blocker is not the weights and not their licence, it is the *dependency closure* — see its row for
the four mutually exclusive pins. Vendoring an artifact into this image cannot fix a package that
cannot be installed beside `rdkit`, so it takes a different shape (its own image, reached as a
`url:` connector) and does not belong under this heading.

# Architecture programme: what is deferred, and exactly how to resume it

`tasks/todo.md` is the plan; `BACKLOG.md` is the one-line queue. This file holds the detail behind
the rows that were deferred while the programme ran in an environment with **no LLM gateway
credential, no cluster and no human on the identity-provider side**. Each entry states *what*, *why
not now*, the *trigger* that makes it workable, the *files* it touches and the *first concrete step*.
It describes what is true of the tree today; check an entry against `HEAD` before working it, and
delete it in the commit that closes it.

Contents: A. blocked on a model gateway · B. needs a cluster, a tenant or a person · C. gated on
time or on a measurement · D. follow-ups the reviews recorded · E. process hazards · F. companion
repositories.

## A. Blocked on a model gateway (no `CHEMCLAW_LLM_*` in this environment)

The credential variable is literally named `API-KEY` where it exists; it was never visible to the
sessions that built this. Live arms use `claude-haiku-5-5` against `https://api.anthropic.com`
(owner instruction). Nothing here ships without the live arm: the owner decision
`D-2026-10-08-model-facing-text-changes-ship-behind-an-evaluation` applies.

### A1. Rewrite model-facing text in batches (W2.15–W2.17)
- **What.** Tool docstrings, schema class docstrings, `ModelProse` constants, prompt blocks and
  `SKILL.md` bodies still carry history. One batch = one tool family (one fleet server, or one core
  `*_tools.py` plus its schema classes). A fleet batch bumps that connector's `contract_version`
  minor. Prompt blocks and skills are the last batches, each block on its own.
- **Why not now.** The ship rule needs a control arm and a candidate arm on a real model, at least
  three runs each; the noise floor is the control arm's own run-to-run spread.
- **Trigger.** A gateway credential in the environment that runs the live arm.
- **Files.** `make model-text` (inventory → `schema/model-text/inventory.json`), `make
  model-text-eval`, `make live-ab`, `make eval-strict`, `make eval-baseline-check`,
  `tests/test_context_floor.py` (`CEILINGS`, `PREFIX_BOUND`), `tests/test_prose_contract.py`,
  `data/evals/probes/`. The core schema dump used to prove "nothing changed" is 75 entries with md5
  `2896b1be5119a4cced67150019306215`; any intended change moves it, so re-baseline it per batch.
- **First step.** Run `make live-ab` with the current text as both arms, three runs each, and record
  the control spread per metric (tool-selection accuracy, first-call schema errors, refusal
  correctness, probe-rubric success, tokens and cost per turn). That is the noise floor; then start
  with the smallest fleet server.
- **After each shipped batch.** Lower `CEILINGS`/`PREFIX_BOUND` to the measured prefix (W2.16) and put
  the eval table in the PR description (W2.17).

### A2. Merge the deepagents/langchain/langgraph upgrade (W5.2)
- **What.** Branch `claude/w5-upgrade-upstream` carries the upgrade. It is **held**: the upgrade
  changes what the model reads (tool descriptions generated by upstream middleware, system-prompt
  fragments), so it merges only after A1's text evaluation shows it is not worse.
- **First step.** Merge current `main` into it (expect conflicts in `agent/langgraph_agent.py`,

  `docs/planning/upstream-issues/01–07`; filing them needs write access to `langchain-ai/deepagents`,

### A3. Delegation re-check (W5.14)
- **What.** After the upgrade, re-run `make live-delegation` (`D-2026-09-27`). If delegation still
  does not pay, ship `agent_helper_roster` **off** by default (its surface stays available).

### A4. Make a semantic embedding provider the shipped default (W7.1 proper)

- **Related.** `embedding_request_dimensions` (set when the model can truncate) must equal

### A5. Retrieval eval in CI on the real provider (W7.3)
- **What.** The `evals/retrieval` harness on the committed corpus with a recall@k floor; the live

### A6. First live re-embed

### B3. UI pods: egress and affinity
- No chart deploys the UI; `Chemclaw3_ui` ships no NetworkPolicy. In a default-deny namespace add one

### B4. Backup and restore on a real CloudNativePG cluster
- **What.** `deploy/helm/chemclaw-postgres` (a separate chart, installed before the application
  chart) and `docs/guides/runbook.md` §(xiii-b) are schema-validated (`kubeconform` against the CRD

  real operator: the Barman Cloud plugin manifests, the `import` and `recovery` bootstraps, the CNPG
  metric names in the runbook (written from memory, marked "confirm against your version"),
  `immediate: true` with `method: plugin`, `Database`/managed-role objects.
- **Steps.** Install CNPG, cert-manager and the plugin; create a versioned bucket and a Secret
  `chemclaw-backup-keys`; install the chart; check the `Backup` completes and
  `status.firstRecoverabilityPoint` is set; write rows, note a timestamp, write more, restore to that
  `targetTime` in a scratch namespace (`recovery.rehearsal: true` writes nothing to the bucket); run
  the by-hand checks; time the restore against `rtoSeconds`.
- **Decisions owed.** The data-protection owner confirms the 30-day default `retentionPolicy`; the
  erasure-on-restore policy requires the operator to log every `make user-erase APPLY=1` outside the
  database (`cli/erase_actor.py::main` keeps no ledger).
- **Gate.** Run `make restore-drill` and one real-cluster rehearsal before W4.9 deletes the git path.

### B5. Flip `calc_transport` to `rpc` (then W6.4)
All five must hold: (1) in-cluster `make bench-backend-rpc` cache-hit p50 ≤ 10 ms (loopback: 5.5 ms
rpc vs 44.9 ms mcp); (2) a cluster run of a durable calc job and a labelling drain on `rpc` with
Temporal retry classes confirmed (`CalcBusyError` retries; `CalcToolError` and `CalcTimeBudgetError`
do not); (3) no hop with a shorter idle or read timeout (mesh sidecar, LB, ingress at 60 s) cuts a
long call — TCP keepalive is set, L7 timeouts are not helped by it; (4) a fleet decision on `/rpc`
having no `cancel_on_timeout` counterpart (the handler runs to completion after a client timeout and
a retry can run beside the orphan) or the orphan risk recorded as accepted; (5) the fleet chart's
`MCP_ALLOWED_HOSTS` covers the Service name:port, and every deployed backend reports
`contract_version` ≥ 1.1.0 within major 1. The contracts tag `contracts-v1.1.0` could not be pushed
from a session (the proxy rejects tag pushes).

### B6. Kept connector sessions vs fleet replicas
- The measured saving (open p50 112 ms → 22 ms, 40 → 8 requests per turn, 8 real servers) is at one
  pod per server. The fleet Services are plain ClusterIP without `sessionAffinity`, and each MCP
  session lives in one pod's memory, so with N replicas a kept session's ping lands on a pod that
  does not know it with probability ≈ (N−1)/N and the pool replaces it (correct, slower).
- **Fix (in `Chemclaw3-mcp`).** Run FastMCP with `stateless_http=True` (the kit's `sessions.py`
  anticipates it) or add `sessionAffinity: ClientIP` with `timeoutSeconds` above 300 to
  `servers/*/deploy/service.yaml`. **First step.** Measure the hit rate on a 2-replica kind
  deployment. The same hazard already exists for parallel tool calls and the GET stream within a turn.

### B7. W4.9 — delete the git knowledge path

  on a copy of the real corpus (B4).
- **Delete.** `kg/git_writer.py`, `BatchingNoteWriter`, the per-pod clone, `deploy/knowledge-sync.sh`,

## D. Follow-ups the reviews recorded (code, no external trigger)

- **Retry classes (`durable/retry.py`).** Nothing sizes `schedule_run_timeout_seconds` or job
  ceilings against the new IO/REMOTE windows.
- **Postgres note store (`kg/postgres_store.py`).** `neighborhood` always walks to `hops` (cost
  hops × edges; callers clamp to `graph_max_hops`); `search` with a common term adds ~60 MB RSS at
  20 k notes — push the cap into SQL; `current_successors` is level-wise (one statement per level); a single-snapshot
  `view` method for `expand_note` (the note view is read in several steps today); the trigram index
  is proven usable but not shown to beat a seq scan at 20 k small notes; a pooled
  first-borrow-then-`SET TRANSACTION` hazard in `protocols/store.py::page`.
- **Embedding width.** Widths over 2000 need a `halfvec` expression index and matching queries;
  superseded sibling columns need a documented drop procedure (and `VACUUM`); the external-store
  re-embed write cannot be made race-free across two systems; the note re-embed still reads through
  `reindex_notes` on the checkout until `kg_store=postgres`; the scheduled `reembed_stale_documents`
  duplicates spend with a running job (accepted, stated).
- **Kept connector sessions.** No pool metric or dashboard (needs a Helm dashboard panel for
  `test_every_declared_metric_has_a_consumer`); `traceparent` on a kept connection is the
  turn-level span at checkout; a server dying mid-turn still fails that call after the request
  timeout; `connectors/server.py`, `queued_call.py` and the interactive worker build their own
  sessions.
- **Backend RPC.** NaN/infinity: the request is refused client-side, the answer is serialised by the

- **`open_session`.** With several teardown leaves and no body error, `_surfaced` leaves the group as

  Temporal outside the cluster or with non-SQL visibility owes the same contract; PgBouncer as CNPG

- **`spend/` (W5.6).** The four middleware (`enforce_loop_cap`, `enforce_spend_cap`,

## E. Process hazards worth keeping

- **A structure test fails in CI long after a narrow local run is green.** Before pushing, run every
  `tests/test_*.py` that scans `src/` (`grep -l "rglob\|ast.parse\|iter_python_files\|SRC\b"`), plus
  `helm`/`caplog`/`configure_logging` users, serially in sorted order in one pytest invocation, and the
  whole-repo `mypy src examples tests` — a narrowed mypy missed a file twice.
- **Two PRs green alone can break `main` together** (a test pinned an exception class that another PR
  deliberately changed). After a sibling merges, merge `main` into the open branch and re-run its
  structure set; do not trust the last green.
- **A full (generation-2) garbage collection holds the interpreter lock for its whole duration.**
  On a 2.5-million-object heap one pass took 1.5–1.7 s and stalled the event loop whichever thread
  triggered it. Tests that measure loop stalls freeze and disable the collector in their window; in
  production the stall is real. Candidate fix: `gc.freeze()` after startup in the API and workers,
  measured against RSS.
- **`tests/served.py::ServerThread`** leaves uvicorn's loggers non-propagating with their own
  handlers for the rest of the process; no test depends on it today. Snapshot/restore there.
- **`tests/recorded_workflow_histories.py::_replay_on_a_private_loop`** is still inherently
  timing-sensitive (whether the SDK parks depends on its shutdown race); if it flakes, make `wedged`
  deterministic in the test.
- **`tests/test_connector_job_workflow.py::test_…[wrapper-headroom-under-a-busy-queue]` hung once.**
  The wrapper kept retrying `deliver_message_activity`, which that test's late worker does not
  register, until pytest's 180 s timeout killed the whole session (16 minutes in); a re-run of the
  same commit passed. Not root-caused: find why the wrapper reaches the delivery activity there (a
  settings-dependent delivery channel?) and register or stub it in the test.
- **Disk.** Agent worktrees and virtualenvs of several hundred MB each filled the volume once
  (110 MB free). Remove a worktree when its branch is pushed and its agent is done; keep scratch out of
  the repo.
- **CI cost.** The `check` job is ~45–59 minutes serial and its job bound is 90 (it was 60 and
  cancelled two green runs at the validator steps after the tests passed in 59 minutes); any push to an open PR restarts it, and
  `main` moving while a PR waits turns a green PR into a conflicted one. Merge sequentially, resolve
  the conflict immediately, and prefer one push per PR per cycle.
- **A branch with only merged history cannot be deleted through the git proxy**
  (`claude/w3-parallel-collect` is a throwaway); tag pushes are rejected.

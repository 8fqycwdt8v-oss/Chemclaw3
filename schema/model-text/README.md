# `model-text/` — every string a model reads

`inventory.json` lists the model-facing text of this repository, one entry per text, regenerated by
`make model-text` and held current by `tests/test_model_text_inventory.py`. It is the input of the
text-edit evaluation (`docs/guides/model-text-evaluation.md`): an edit to what a model reads changes
this file, so the pull request that makes it carries the diff.

## An entry

| field | meaning |
| --- | --- |
| `id` | `tool:<name>`, `block:<n>`, `safety:<n>`, `skill-description:<name>`, `skill-body:<name>`, `schema:<module.Class>`, `prose:<module>:<name>`, … — the file is sorted by it |
| `kind` | what sort of text: a tool schema (`tool-schema`, `mcp-tool-schema`, `upstream-tool-schema`), a docstring, a schema class, a prompt block, a profile's text, a skill's listing line or body, a `ModelProse` constant, a response format, an MCP output schema |
| `owner` | `file:symbol` where the words are written; `upstream:…` for a framework tool this repository does not write |
| `residence` | `every-request` (in the default profile's prefix on every model call), `conditional` (a profile, or a tool or block the default surface does not bind), `on-demand` (a skill body, a tool result, a call to another model) |
| `tokens`, `chars` | size by the counter `tests/test_context_floor.py` and `agent/compaction.py` use (`count_tokens_approximately`: chars/4, plus 3 per message) |
| `sha256` | the first 16 hex digits of the text's hash, so any edit moves the file even if the size does not |
| `also_counted_in` | the entries that already contain these words (a docstring is inside its tool's schema), so it adds to no total |

A text is measured as the model is sent it: a tool is `convert_to_openai_tool` of the `BaseTool` the
compiled default-profile graph binds, middleware tools (`task`, `write_todos`, the filesystem
verbs) included. The per-process framing nonce is replaced by zeros of the same length, so the file
does not change from one process to the next.

## `environment` and `overlay`

`environment` records the settings that decide what a default turn is built from (the connector set,
the templates and skills, the exhibit tools, the helper roster), with paths inside the repository
written relative to it. Two inventories are comparable only when these agree, and the text
evaluation refuses two that do not. `overlay` is the digest of the model-text overlay the inventory
was built under, and is `null` here: `make model-text` refuses to write this file while an overlay
is set, so candidate text cannot be committed as the shipped text's inventory.

## `prefix`

The default profile's per-request prefix, in the parts the context floor charges:

- `tool_schemas` — every bound tool, this repository's servers served in memory. Per tool this is
  the number `tests/test_context_floor.py` measures, and `tests/test_model_text_inventory.py` holds
  the two equal.
- `instructions` — the system prompt as assembled for the bound surface.
- `skill_descriptions` — the maximal skill listing, before the capability narrowing.

`total` is their sum and is what the ship rule compares. It is **not** the floor's total, and is
meant to be smaller: the floor also charges the deepagents middleware's own prompt sections, the
skill listing's formatting (name and path beside each description) and the blocks only a
fleet-served deployment binds. The gap is therefore a measured constant of text this repository does
not write, and the test holds the inventory's `total` at or under the floor, and the floor under
`CEILINGS`.

## Python version

`python` records the interpreter. The inventory is measured under the image's (`[tool.mypy]
python_version`): from 3.13 the compiler dedents docstrings, and a tool description is its raw
docstring, so the same tool costs fewer tokens there than in the image. Regenerate with
`uv run --python 3.11 python -m chemclaw.cli.model_text_inventory` where the default interpreter
differs; the staleness test skips, naming this, on any other.
